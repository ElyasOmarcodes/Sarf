# تصريف — Taṣrīf

> د علم صرف د بابونو د اعلال جوړونکی
> **الصَّرْفُ أُمُّ الْعُلُومِ وَالنَّحْوُ أَبُوهَا**

یوه کلمه ولیکئ — لکه **ضرب**، **دحرج**، **اکتسب**، **قال** — او اپلیکېشن یې
باب، قسم، صرف صغیر او بشپړ صرف کبیر درکوي؛ او د هرې صیغې اعلال د خپلې قاعدې،
تعلیل او د کتاب د مرجع سره وړاندې کوي.

---

## څه کوي

| برخه | تفصیل |
|---|---|
| **پېژندنه** | ۶ اقسام (ثلاثي/رباعي/خماسي × مجرد/مزید)، ۷ اقسام (سالم، مضاعف، مهموز، مثال، أجوف، ناقص، لفیف)، باب، وزن، زیادت، مصدر |
| **صرف صغیر** | د باب لنډیز په یوه کرښه — هره برخه پرې کلیک کیدونکې |
| **صرف کبیر** | ۲۱ جدوله: ماضي/مضارع × معلوم/مجهول، جحد، نفي، لن، امر، نهي، نون تاکید |
| **مشتقات** | اسم فاعل/مفعول، ظرف، **اسم آله (صغرى/وسطى/كبرى)**، تفضیل، مبالغه |
| **اعلال** | هر ګام: اصل → نتیجه، د قاعدې نوم، تعلیل، او د کتاب مرجع |
| **ژبې** | پښتو · فارسی · العربية · English — د تعلیلاتو په ګډون |

## سرچینې

هره قاعده له دې کتابونو راغلې ده، او هر transformation خپله مرجع ورسره لري:

- **شذا العرف في فن الصرف** — أحمد بن محمد الحملاوي
- **إرشاد الصرف** — مولانا عبد الكريم القلاتوالي (فارسي اصل)
- **إرشاد الصرف باللغة العربية** — تعریب منظور أحمد شاه الدیروي

اصلي متنونه: [`sources/`](sources/) · منظمه خلاصه: [`docs/sarf/`](docs/sarf/)

> 🔴 **د پروژې شرط:** هر ځل چې کوډ لیکل کیږي، باید د دې کتابونو د اصولو مطابق وي.
> تفصیل: [`CLAUDE.md`](CLAUDE.md)

## جوړښت

```
lib/
  sarf/          ← خالص Dart انجن، له Flutter پرته — د ټسټ وړ
    arabic.dart      حروف، حرکات، رسم‌الخط او rendering
    models.dart      بنا، اقسام، ۱۴ صیغې، ۶ بابونه
    awzan.dart       د وزنونو جدول + د پېژندلو skeletons
    lexicon.dart     سماعي طبقه — باب او مصدر
    rules.dart       نومول شوې قاعدې + تعلیل په ۴ ژبو
    conjugator.dart  د اصل جوړول + د اعلال pipeline
    analyzer.dart    کلمه → تحلیل (څو احتمالات، درجه‌بندي شوي)
    tasrif.dart      صرف صغیر · صرف کبیر · مشتقات
  core/          ← تنظیمات، ژبې، تیم
  ui/            ← Material 3 Expressive سکرینونه
test/            ← ۵۳ ټسټونه (انجن + widget)
```

**بنسټیزه پرېکړه:** هېڅ بڼه له جدوله نه اخیستل کیږي — هره یوه **جوړیږي**.
لومړی `قَوَلَ` جوړیږي، بیا `قَالَ` ترې راوځي، ځکه چې همغه منځنی ګام هغه څه دی
چې زده کوونکی یې غواړي وویني.

## جوړول

```bash
flutter pub get
flutter test        # ۵۳ ټسټونه
flutter analyze
```

پلیټ‌فارم فولډرونه (`android/`, `ios/`, `windows/`) په CI کې د `flutter create`
په واسطه جوړیږي، نو په ریپو کې نه ساتل کیږي.

### د کمپایل پایلې

GitHub Actions هر push کې دا جوړوي:

| هدف | فایل | یادونه |
|---|---|---|
| Android | `Tasrif.apk` | arm64، release، obfuscated |
| iOS | `Tasrif-unsigned.ipa` | بې signature — AltStore/Sideloadly ته |
| Windows | `Tasrif-Windows.zip` | ↓ لاندې یادونه ولولئ |

> **د ویندوز د «یوازې یو فایل» په اړه:** د Flutter ویندوز release یوه **پوښه** ده —
> `tasrif.exe` + `flutter_windows.dll` + د پلګ‌ان DLL‌ونه + `data/` (ICU او assets).
> exe یوازې پرته له هغو نه پرانیستل کیږي، نو zip باید ولري یې. هغه څه چې **کمولی**
> شو د build ضایعات دي (`*.pdb`, `*.exp`, `*.lib`) — او هغه CI کې غورځول کیږي،
> چې اصلي وزن همدا و.

### Signing (اختیاري)

که دا Secrets ورزیات کړئ، artifacts سیګنیچر مومي؛ که نه وي، بې سیګنیچره جوړیږي:

`ANDROID_KEYSTORE_BASE64` · `ANDROID_STORE_PASS` · `WINDOWS_PFX_BASE64` · `WINDOWS_PFX_PASS`
